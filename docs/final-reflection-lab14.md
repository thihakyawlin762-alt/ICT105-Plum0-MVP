# Final Reflection

## 1. What We Built

During this project, our team successfully developed *Smart Assignment Tracker*, a web-based assignment management system designed to help university students organize coursework, monitor deadlines, and manage assignment progress efficiently. The prototype also includes a Lecturer Dashboard that enables lecturers to review assignment records, monitor completion rates, and view course analytics. The system was implemented using HTML, CSS, JavaScript, and LocalStorage without requiring a backend database.

---

## 2. What We Learned About Users

Throughout customer discovery, validation, and user testing, we learned that students prefer a simple and centralized platform for managing assignments rather than relying on paper notes or multiple messaging applications. Users valued clear navigation, organized dashboards, search functionality, and deadline tracking. Lecturers also appreciated having a centralized overview of assignment progress and student performance.

---

## 3. What We Learned About Requirements

We learned that well-defined functional requirements helped guide prototype development and kept the project organized throughout each laboratory. Mapping every implemented feature to specific requirement IDs made it easier to verify completeness, conduct testing, and maintain documentation consistency across the project.

---

## 4. What We Improved After Testing

Based on user testing feedback, several improvements were made before the final prototype:

- Improved Student Dashboard layout and navigation.
- Completed the Lecturer Dashboard functionality.
- Enhanced search and filtering performance.
- Improved assignment status tracking.
- Fixed interface consistency issues across multiple pages.
- Improved responsive layouts and overall usability.
- Refined documentation and demonstration workflow.

---

## 5. What Was Difficult Technically

The most challenging technical aspects included maintaining consistent LocalStorage synchronization across multiple pages, organizing modular JavaScript files, ensuring data updates were reflected correctly throughout the system, and maintaining a consistent user interface while expanding the prototype. Coordinating documentation, GitHub organization, and prototype development simultaneously also required careful planning.

---

## 6. What We Would Improve Next

If additional development time were available, we would implement:

- Multi-user authentication.
- Cloud database integration.
- Email and notification services.
- Mobile application support.
- Calendar synchronization.
- Advanced lecturer analytics and reporting.
- Real-time collaboration between students and lecturers.

These improvements would transform the prototype into a production-ready academic management platform.

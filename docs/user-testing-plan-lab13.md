# User Testing Plan

## 1. Testing Objective

The objective of this user testing session is to evaluate whether university students and lecturers can successfully use the Smart Assignment Tracker prototype to manage assignments, monitor deadlines, search assignment records, and understand dashboard information before the final MVP release in Lab 14.

The testing also aims to identify usability issues, confusing workflows, and opportunities for improvement before the final presentation.

---

## 2. Test User Profile

| User Type | Number of Testers | Why This User Type Matters |
| --- | ---: | --- |
| University Student | 3 | Primary users who create, edit, search, and complete assignments. |
| Lecturer | 1 | Reviews assignment records, monitors student progress, and evaluates dashboard analytics. |

---

## 3. Testing Tasks

| Task ID | User Task | Related Requirement | Success Criteria | Observation Focus |
| --- | --- | --- | --- | --- |
| T01 | Open the Landing Page and explain the purpose of the Smart Assignment Tracker. | FR-01 | User correctly explains the purpose of the system. | Landing page clarity and value proposition. |
| T02 | Log in and access the Student Dashboard. | FR-01 | User successfully enters the dashboard without assistance. | Navigation and login usability. |
| T03 | Create a new assignment using the Add Assignment page. | FR-02 | User completes the assignment form successfully. | Form clarity, validation, and ease of use. |
| T04 | Search for an assignment using the Search page. | FR-03 | User finds the correct assignment quickly. | Search efficiency and filter usability. |
| T05 | Edit an existing assignment and update its status. | FR-02 | User updates assignment information successfully. | Editing workflow and button visibility. |
| T06 | Mark an assignment as completed and verify it appears in Completed Assignments. | FR-02 | Assignment status updates correctly. | Completion workflow and status tracking. |
| T07 | View the Lecturer Dashboard and explain the dashboard information. | FR-04 | User understands charts, assignment statistics, and student progress. | Dashboard readability and usefulness. |
| T08 | Review notifications and upcoming deadlines. | FR-05 | User identifies upcoming assignments and reminders correctly. | Notification visibility and deadline awareness. |

---

## 4. Testing Procedure

1. Introduce the purpose of the Smart Assignment Tracker prototype.
2. Explain that the testing session is conducted for academic purposes only.
3. Ask each tester to complete every task independently.
4. Observe the tester without providing guidance unless they become completely stuck.
5. Record task completion, user comments, usability issues, and suggestions.
6. Ask the tester for overall feedback after all tasks are completed.
7. Summarize the results for future improvements before Lab 14.

---

## 5. Ethical Reminder

This testing session is conducted solely for ICT105 coursework and prototype evaluation.

No unnecessary personal or sensitive information will be collected. All feedback, observations, and comments will be used only to improve the Smart Assignment Tracker prototype before the final MVP presentation.
